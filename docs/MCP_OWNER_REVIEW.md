# مراجعة التقرير في كلود عبر MCP · Owner review of client reports via MCP

**قرار المالك (2026-10-20):** التقرير يُنتَج في Silk كالمعتاد، ثم يراجعه المالك
وينقّحه داخل **كلود (Desktop أو Code)** على اشتراكه الشخصي — لا مرحلة تلميعٍ
مدفوعة داخل المسار — ثم يعيده إلى Silk فتصدر ملفات العميل (Word/PDF/Markdown)
من النصّ المنقَّح بالقالب الرسمي نفسه. المالك يرسل الملف للعميل بنفسه.

> **تكلفة الخادم في هذا المسار: صفر نداء كلود.** كل فحصٍ عند الإرجاع حتمي
> (`silk_refined_report` + `silk_export_gate`).

## المسار في ثلاث خطوات

1. **`list_studies`** — قائمة الدراسات المخزَّنة (المعرّف، المنتج، السوق، الحكم).
2. **`get_report`** — **نصّ الكاتب المخزَّن** القابل للتنقيح (Markdown بعناوينه
   وعناصر `{{…}}` التي تُملأ آلياً عند التصيير)، مع قرار بوّابة التسليم الحالي
   وأسباب الحجب إن وُجد. تعود كتلتان: ملاحظة قصيرة ثم النصّ نفسه. هذا هو ما
   يُعاد في الخطوة ٣ — لا المستند المعروض للعميل (وإلا تداخل قالبٌ داخل قالب).
   دراسةٌ محجوبة يمكن تنقيحها هنا أيضاً: الملاحظة تسمّي أسباب الحجب.
3. **`submit_refined_report`** — النصّ المنقَّح كاملاً. الخادم يرفض **بلا حفظ**:
   - رقماً/نسبةً/سنةً غير واردة في النصّ الأصلي (`new_figures`) — لا نخمّن الأرقام؛
   - عنواناً غائباً (`missing_heads`) — القالب يقرأ العناوين حرفياً؛
   - عنصر `{{…}}` غائباً أو جديداً (`missing_placeholders` / `new_placeholders`) —
     السجلّ يملؤه ويرصد به البيانات البائتة؛
   - نصاً أقصر من نصف الأصل (`truncated`) — قسمٌ واحد ليس تقريراً؛
   - ما تحجبه بوّابة التسليم نفسها (`quality_gate_fail`: بلاغات المالك، الادّعاء
     الحادّ بلا سند، تسريب لغة النظام…).
   القبول يخزّن النصّ مكان تقرير الكاتب، ويحفظ الأصل مرّةً واحدة في
   `report_original`، ويعيد روابط التصدير الثلاثة.

حدود الفحص الحتمي (معلَنة، تبقى على المالك عند المراجعة):
- فحص الأرقام **عضويةٌ** لا ارتباط: رقمان واردان قد يُركَّبان في ادّعاء جديد
  («نمت 64% منذ 2021») ويمرّان — القاعدة ٥ في وصف الأداة تمنعه، والمالك يقرأ.
- ادّعاء نوعي أو اسم جهة لا سند له في الأدلة (كلود يرى النصّ لا سجلّ الأدلة).
- بوّابة الإرجاع تُقيَّم بالنثر المخزَّن فقط: سطوح التصدير قد تستدعي كلود (مدفوعاً)
  لصياغة قسمٍ بلا سرد قبل البوّابة؛ هذا المسار لا يستدعيه بقرار المالك، فقد يُرفَض
  هنا ما كان التصدير العادي سيكمله بنداء — الرفض يسمّي القسم.

## الإعداد على جهاز المالك

يلزم `python3` فقط (الخادم بالمكتبة القياسية، بلا `pip install`) ونسخة من الريبو.

**Claude Desktop** — `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "silk": {
      "command": "python3",
      "args": ["/PATH/TO/556-railway/tools/silk_mcp.py"],
      "env": {
        "SILK_BASE_URL": "https://<railway-domain>",
        "SILK_API_KEY": "<SILK_API_KEY على Railway>"
      }
    }
  }
}
```

**Claude Code:**

```bash
claude mcp add silk -e SILK_BASE_URL=https://<railway-domain> -e SILK_API_KEY=<key> \
  -- python3 /PATH/TO/556-railway/tools/silk_mcp.py
```

مثال طلب داخل كلود بعد الربط: «اسحب نصّ الدراسة ١٢ ونقّحه بلغة تجارية أوضح
دون تغيير أي رقم أو عنوان أو عنصر {{…}}، ثم أعده إلى Silk». كلود يستدعي الأدوات
الثلاث بالترتيب، وعند الرفض يعيد الملاحظات فيصلحها ويعيد الإرسال.

## التحقّق بعد النشر (الدلو الثاني)

على دراسة حقيقية (لا العيّنة الاصطناعية): `get_report` ← تنقيح ← `submit_refined_report`
← افتح `GET /analyses/{id}/report.docx` وقارن. الحكم على جودة التنقيح معلَّق حتى
تمرّ دراسة فعلية بالمسار.

## المراجع في الشيفرة

- `tools/silk_mcp.py` — الخادم (stdio، JSON-RPC، ثلاث أدوات).
- `silk_refined_report.py` — الفحوص الحتمية وعقدة التقرير الجديدة.
- `api.py` — `GET`/`POST /analyses/{analysis_id}/report/refined` و`_refined_gate`.
- `tests/test_mcp_refined_report.py` — أقفال المسار كلّه.
