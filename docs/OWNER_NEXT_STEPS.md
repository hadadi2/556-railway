> **الغرض.** ثلاث قوائم جاهزة للنسخ: (١) ضبط Railway لرؤية منصّة المصانع حيّة
> لأول مرة، (٢) الأعلام المطفأة التي تنتظر قرار تفعيلك، (٣) أوامر المهام

## ١ — رؤية المنصّة حيّة (لماذا لم ترَ شاشة الدخول حتى الآن)

الشاشة موجودة في الشيفرة على `https://<نشرك>/platform` — لكن الدخول يتطلب
متغيرات لم تُضبط بعد. على Railway → Variables أضف:

| المتغير | القيمة | لماذا |
|---|---|---|
| `SILK_PLATFORM_SECRET` | سلسلة عشوائية طويلة (32+ حرفاً) | توقيع الجلسات والروابط — بدونه سرّ عابر يُبطل كل شيء عند إعادة التشغيل |
| `SILK_PLATFORM_REQUIRE_SECRET` | `1` | يرفض الإقلاع بصوت عالٍ إن غاب السرّ (بدل الخدمة بسرّ فانٍ) |
| `SILK_PLATFORM_SECURE_COOKIES` | `1` | كوكي الجلسة عبر HTTPS فقط |
| `SILK_SEED_ADMIN_PASSWORD` | كلمة **بحرف كبير وصغير ورقم، ٨+ أحرف** (مثال: `Silk2026x`) | بوابة البذر: بدونها القاعدة تقلع بصفر مستخدمين وكل دخول يُرفض «بيانات غير صحيحة». كلمة تخالف السياسة تُرفض ويسمّي `/health` المتغيرَ المخالف بالاسم |
| `SILK_PLATFORM_SCHEDULER` | `1` | بدونه لا يخرج بريد الحملات ولا يجري التصفير الشهري للحصص |
| `ANTHROPIC_API_KEY` + `SILK_API_KEY` | مفتاحاك القائمان | **منذ 2026-08-18 دراسة المنصّة تشغّل محرّك البحث العميق نفسه (~١٥ دقيقة، ≈2$ للدراسة من السقف اليومي)** — غيابهما يجعل الإطلاق يُرفَض برسالة معلَنة `engine_not_ready`، لا دراسات فارغة |
| `SILK_PAID_DAILY_CAP` | سقف يناسب دراسات يومك | كل دراسة منصّة عميقة تحجز تفعيلة واحدة (نفس عدّاد `/research`) |

ثم أعد النشر، وافتح:
1. `https://<نشرك>/health` → تحقق أن `platform_ready.seeded: true` و`users ≥ 1`
   (وأي مشكلة بذر تظهر هنا باسم المتغير — لا حاجة لسجلات Railway).
2. `https://<نشرك>/platform` → شاشة دخول بهوية سِلك.
3. ادخل بـ`admin@silk.local` + كلمة `SILK_SEED_ADMIN_PASSWORD`.
4. سترى: حسابات المصانع (موّل/غيّر الباقة/اضبط **حصّة المستخدم**)، بطاقة
   **تكاليف البحث** (أدمِن حصراً — قرارك)، إعادة تعيين كلمات المرور.
5. حسابا مصنعين مبذوران للتجربة: `owner@factory-a.local` (فضية)
   و`owner@factory-b.local` (ذهبية) بكلمات `SILK_SEED_FACTORY_A_PASSWORD`/
   `..._B_...` إن ضبطتهما (وإلا وُلّدت عشوائياً — اضبطهما لتعرفهما).

**فحص ما بعد النشر بنقرة:** GitHub → Actions → «Post-deploy smoke (opt-in)» →
Run workflow (بعد ضبط سرَّي `SILK_LIVE_BASE_URL` و`SILK_LIVE_API_KEY` في
Settings → Secrets مرة واحدة).

## ١ب — دليل استخدام المنصّة بعد التحوّل (2026-08-17) · how the platform works now

المنصّة الآن **لدراسات السوق حصراً** (قراراتك الثلاثة): لا عملاء محتملين ولا
رسائل ولا قمع — حُذفت نهائياً، ومنصّة التنقيب المستقبلية ستكون نظاماً منفصلاً.

**رحلة المصنع:**
1. يفتح `رابطك/platform` → صفحة الهبوط → «الدخول إلى البوابة».
2. «+ دراسة جديدة»: اسم المنتج (إلزامي)، السوق المستهدف ورمز HS اختياريان —
   أو يرفع صورة المنتج ويضغط «تحديد المنتج والرمز من الصورة» (يتطلب
   `SILK_IMAGE_INTAKE=1` + مفاتيح كلود المضبوطة سلفاً).
3. «إطلاق» → محرّك سِلك يشتغل آلياً؛ الجدول يعرض «قيد الإعداد» مع «مضى/متبقٍ»
   (مقيس من دراسات سابقة أو موسوم «تقديري»).
4. عند الاكتمال: «عرض التقرير» في المنصّة + «تنزيل التقرير (PDF)» — المُسلَّم
   النهائي PDF غير قابل للتحرير (طلبك 2026-08-17). فشلٌ = تعود «مسودّة»
   بسبب معلن **وتُرجَع حصّته** — لا حصّة تُحرق بلا ناتج، **بما فيها**
   التشغيلة التي تكتمل بلا أي بيانات من المصادر (تُعلن فاشلة الآن).

**تحكّمك أنت:**
- الحصص: باقة الحساب (شهرية) + «الحصّة» لكل مستخدم من لوحتك — البوابة
  الوحيدة («الباقة فقط»: لا خصم محفظة لكل دراسة).
- «كل الدراسات»: إشراف حيّ على طلبات كل المصانع (من طلب، ماذا، الحالة، سبب
  أي فشل، **مدة التشغيل وعدّادات الجلب حية/مخزن**). «تكاليف البحث» تبقى
  لك وحدك.
- «فحص المصادر الآن» (`GET /platform/admin/diagnostics`): نقرة واحدة تجسّ
  كومتريد/البنك الدولي/بقية المصادر حيّاً من خادمك وتريك حالة كلٍّ وتلميح
  العلاج — أول ما تفتحه إذا خرجت دراسة «دون أي بيانات من المصادر».

**لماذا خرج تقريرك الأول فارغاً؟ (تشخيص 2026-08-17):** التشغيلة اكتملت
والمصادر كلها فشلت (شبكة/حد معدل) فخرج تقرير بلا أرقام. الآن هذه الحالة
**فشل معلن** يعيد الدراسة مسودّةً ويُرجع الحصّة. ولرفع فرص نجاح الجلب:
أضف `COMTRADE_API_KEY` في Railway — **تسجيله مجاني** على
comtradedeveloper.un.org، وبدونه تعمل نقطة «المعاينة» المحدودة السقف
التي تفشل كثيراً تحت الضغط (`silk_data_layer.py:66`).
- كل تشغيلة دراسة مصنع تجري **بلا إضافات كلود** افتراضاً (الصمّام
  `SILK_PLATFORM_STUDY_AI` أدناه) — فكلفة النقرة الواحدة تبقى في نطاق
  المصادر المجانية حتى تقرر غير ذلك.

## ٢ — قائمة تفعيل الإنتاج: أعلام مشحونة مطفأة تنتظر قرارك

(القاعدة: صمّام الميزة الجديدة يُشحن مطفأً — الدرس ٧٠؛ التفعيل قرارك وحدك.)

| العلم | ماذا يفعل عند التفعيل | شرط ما قبل التفعيل |
|---|---|---|
| `SILK_BACKUP_HOURS=24` | نسخة ليلية متسقة لكل قواعد SQLite **وأرشيف صور المصانع** (`platform_files.tar`) إلى `/data/backups` بدورة ٧ أيام + تنزيل عبر `/ops/backup/{store}`؛ كلُّ طبعة تُفحَص قبل اعتمادها (R5) | لا شيء — **موصى به فور الدمج**؛ ثم اسحب الطبعات خارج الوحدة أسبوعياً (`DEPLOY_RAILWAY.md §٧أ`) |
| `SILK_PLATFORM_NOTIF_RETENTION_DAYS=90` / `SILK_PLATFORM_AUDIT_RETENTION_DAYS=365` | حذفُ الإشعارات **المقروءة** وقيود التدقيق **غير المحميّة** الأقدم من النافذة (R5؛ مطفأة افتراضاً — تنقيةُ بيانات الشراء وحدها تعمل بـ٩٠ يوماً) | قرارك على نافذة الاحتفاظ |
| `SILK_WATCHDOG_ALERT_EMAIL=you@…` | بريد فوري عند سجلّ مراقبة أحمر (خرق عقد) | ضبط SMTP التشغيلي (`SILK_PLATFORM_OPERATOR_SMTP_*`) — وهو مطلوب أصلاً لبريد «نسيت كلمة المرور» |
| `SILK_REQUIRE_PERSISTENT_DATA_DIR=1` | يرفض الإقلاع بلا وحدة تخزين مركّبة فعلاً | `SILK_DATA_DIR=/data` + Volume مركّب (الدرس ٤) — موصى به |
| `SILK_HS_ATTRIBUTE_RESOLVE=1` | حسم رمز HS آلياً من صورة العبوة/الويب | **مشروط بإغلاق G8**: التشغيلات الثلاث المسجّلة في القسم ٣ أدناه (قرار المُشرِف D1) |
| `SILK_WORLD_MARKETS=1` | ترتيب كل دول العالم (Tier-2 بثقة مقيّدة) | مراجعتك لعرض الفئة-2 |
| `SILK_IMAGE_INTAKE=1` | استقبال المنتج من صورة (نداء رؤية مقيس) | مفتاح كلود + رغبتك في الميزة |
| `SILK_PRERUN_ADVISORIES=1` | لوحة استشارات ما قبل التشغيل الموحدة | — |
| `SILK_REQUIRE_HS6=1` | رفض `/research` برمز فارغ قبل أي إنفاق | — (بوابة تأكيد HS تعمل افتراضاً أصلاً) |
| `SILK_PRODUCER_ADVISORY=1` / `SILK_A2_PLAUSIBILITY=1` / `SILK_E_SUBSTRUCTURE_CHECK=1` | استشارات/فحوص إضافية | معايرة حية أولاً (موثقة في `.env.example`) |
| `SILK_PLATFORM_STUDY_AI` | مطفأ | إضافات كلود على تشغيلات دراسات المصانع — فعّله فقط إن رضيت أن تصرف كل نقرة مصنع من رصيد كلود |
| `SILK_IMAGE_INTAKE` | مطفأ | قراءة صورة المنتج (زر «تحديد المنتج والرمز من الصورة») — يتطلب ANTHROPIC_API_KEY + SILK_API_KEY |
| `SILK_PAY_PROVIDER` | فارغ (غير مهيأ) | اختيار مزوّد الدفع (moyasar/tap/stripe) لصفحة الدفع — **التكامل يُبنى بعد قرارك بالمزوّد**؛ اليوم الصفحة تعلن «غير مفعَّل» بصدق وتسجّل الطلبات في التدقيق (تراها في «نظرة عامة») |
| `COMTRADE_API_KEY` | فارغ | **موصى به الآن** — تسجيل مجاني يرفع حد كومتريد؛ بدونه نقطة المعاينة كثيرة الفشل (سبب مباشر محتمل لدراستك الفارغة). منذ R7 يُرسَل ترويسةً لا في الرابط — دخانُ ما بعد النشر في `DEPLOY_RAILWAY.md §٣` |
| `SILK_TRACE_RETENTION_DAYS=30` | فارغ (لا كنس) | R7: كنسُ آثار التشغيل الأقدم من ٣٠ يوماً ساعياً | — |
| `SILK_FORWARDED_ALLOW_IPS` | `*` | R7: تضييقُه إلى نظير بروكسي Railway الفعلي — **إجراء مالك ثلاثيّ الخطوات** في `DEPLOY_RAILWAY.md §٣` (قراءةُ النظير من سجلّ الوصول ثم التحقّق) |
| `/health` مقابل `/ready` (R9) | `/health` مسبارُ Railway: لقطةٌ رخيصة تُجدَّد كلَّ دورةِ حاصد (`probe_age_s`)؛ `/ready` فحصٌ طازج مخنوق للتشخيص اليدوي (503 على سوء التهيئة) | لا شيء — استعمل `/ready` حين تريد الحقيقة الآن |
| Custom Start Command (لوحة Railway) | R9/CI-2: ما دام الحقلُ يحمل أمراً بلا أعلام فهو يغلب `CMD` الصورة فورَ حذف `startCommand` من `railway.json`؛ لذا بقي الملفُّ مرآةً | **أفرِغه في الإنتاج والتجهيز ثم أبلغني** — عندها يُحذَف الحقلُ من الملفّ ويُقلَب قفلُ R0 (`CI-2/SEC-5` معلَّق) |
| `SILK_MAX_BODY_BYTES` / `SILK_PDF_MAX_CONCURRENT` / `SILK_PDF_WAIT_S` | R9: سقفُ حجم الطلب (٢٠ م.ب) وفتحاتُ LibreOffice (٢، بلا انتظار) — افتراضاتٌ معقولة | لا شيء إلا إن كثرت 413 أو `pdf_busy` في السجلّ |

## ٣ — المهام الحية المدفوعة المؤجلة (~$5–10 مرة واحدة، بقرارك)

اخترتَ تنفيذها **بعد** دمج الإصلاحات. تُنفَّذ على خادمك الحي بمفاتيحك
(المفاتيح لا تغادر Railway). عهّد بها جلسة عمل واحدة مخططة — لا ارتجالاً في
ذيل جلسة (توصية السجل نفسها):

```bash
export BASE="https://<نشرك>"
export KEY="<SILK_API_KEY>"
```

**أ) أول أساس لتقييم جودة التقارير** (`evals/scores.json` ما يزال `{}` —
مقارنة الانحدار مسلّحة بلا مرجع). على بيئة بمفتاح كلود (railway ssh أو
محلياً بالمفاتيح):

```bash
python3 -m silk_evals --all          # ٤ حالات ذهبية × تشغيلة حية (~$8-10)
git add evals/scores.json && git commit -m "evals: أول أساس حي مقيس"
# ثم ضيّق سقوف الفجوات الأربعة في evals/golden_cases.json من القياس
# (0.30/0.30/0.45/0.35 → الأساس المقيس + هامش) — توصية السجل: «بوابة
# فضفاضة دائماً أسوأ من لا بوابة»
```

**ب) تشغيلات G8 الثلاث لصمّام حسم HS** (شرط تفعيل
`SILK_HS_ATTRIBUTE_RESOLVE` — جدولها الكامل في
`docs/DEEP_RESEARCH_DECISIONS.md` قيد PR #177):
1. صورة عبوة بنسبة دهن مطبوعة → الرمز يُحسم بوسم «من صورة العبوة».
2. منتج بلا صورة → الحسم من الويب بوسم الرابط.
3. «شاي أخضر معبأ» → **رفض** الحسم الآلي (ترويسة ثنائية المحور) وعرض الحوار.
سجّل الثلاث في السجل ثم فعّل العلم.

**ج) إعادة دراسة «تحليل ٧» بالرمز الصحيح** (~$3): التحليل المُسلَّم يحمل على
الأرجح رمزاً خاطئاً (سوق اليمن مسحوق حليب 040210 لا سائل 040110). قبل الإنفاق
أجب سؤالَي السجل: شكل منتج Nadec الفعلي، ومصدر رقم 22.14M — ثم:

```bash
curl -sS -X POST "$BASE/research" -H "X-API-Key: $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"product":"حليب مجفف","market":"Yemen","hs_code":"040210",
       "hs_confirmed":true,"persist":true,"async_run":true}'
```
